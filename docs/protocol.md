# Phase 1 control protocol, version 1

Rust starts a loopback TCP listener on an ephemeral port and launches the bundled base-R worker with `RSSTUDIO_PORT` and a fresh random 128-bit `RSSTUDIO_SECRET`. The worker unsets these variables and connects to 127.0.0.1. Its first message is `HELLO`, request ID 0, payload `1:<secret>`; Rust accepts only the expected version and secret, subject to a startup deadline. This prevents accidental local connections from being accepted; it is not a sandbox against code running as the same user.

Each frame is a four-byte unsigned big-endian length followed by exactly that many UTF-8 bytes (1 byte to 1 MiB). The payload is `KIND<TAB>ID<TAB>DATA`, with an uppercase ASCII kind, unsigned decimal request ID, and unescaped UTF-8 data. Split on the first two tabs only. NUL is rejected in submitted source. The worker must read partial frames until complete; Rust uses `read_exact`. Invalid framing, invalid UTF-8, or a disconnected control channel fails the session. A dedicated socket reader prevents partial packets from blocking the supervisor.

Rust sends `EVAL` with complete accumulated source, or `SHUTDOWN` (ID 0, empty payload). R answers `DONE`, `ERROR`, or `INCOMPLETE` with the same request ID. Only one evaluation may be in flight. `INCOMPLETE` means no code in that request was evaluated; the GUI retains the source for continuation. R parses before evaluating in `.GlobalEnv`, prints visible values, and reports errors as data. The initial incomplete-input classification depends on R's English parser diagnostic; validate across supported R versions.

The package pane also sends `PACKAGES` with newline-separated validated package names, `INSTALL` with `CRAN` or `BIOC`, a tab, and one validated name, and `LOAD` with one validated name. `PACKAGES` returns `STATUS` with `name<TAB>version-or-<dash><TAB>attached` rows. Installation and loading return `DONE` or `ERROR`; installation output uses the existing stdout/stderr pipes. The worker checks names again, uses fixed repository locations and an R user library, and verifies installation. Only one operation is in flight, so package work and console evaluation share the session queue.

The Environment pane sends `ENVIRONMENT` with an empty payload and receives an `ENVIRONMENT` response containing a bounded JSON snapshot of visible objects in `.GlobalEnv`, or `ERROR`. The worker skips active bindings, limits object and column counts, and samples values. The snapshot stays local unless the user selects an object and the assistant calls its inspection tool. Environment requests use the same single-operation queue as evaluations and package requests.

The Source editor sends `COMPLETE` with a mode (`symbols`, `members`, or `namespace`) followed by tab-separated hexadecimal UTF-8 owner and prefix strings. The worker returns `COMPLETIONS` containing up to 200 matching names and a truncation flag, or `ERROR`. It lists the active workspace and attached packages, reads member names from a named object, or lists exports of an already loaded namespace; it does not evaluate the editor text. Active bindings are skipped for member lookup. Completion shares the session queue and the editor discards or caches responses without applying them to a changed cursor context.

The supervisor provides a private temporary graphics directory via `RSSTUDIO_PLOT_DIR`. During an `EVAL`, the worker may send `PLOT` messages with the active request ID and a payload of `page-id<TAB>plot-NNNNNNNN.png`. The supervisor accepts only generated filenames inside that directory, reads bounded PNG data, deletes the temporary snapshot, and keeps the evaluation pending until its normal completion message. Page IDs let the UI replace a snapshot when code adds a layer, while preserving distinct pages in history. The working graphics device remains open between evaluations; R's explicitly opened devices are not redirected. All temporary graphics files are removed when the session stops.

R's stdout and stderr are separate pipes and never carry protocol messages. Their ordering relative to completion messages is not guaranteed. The UI bounds retained output; control messages and output events include a session generation so late events from a previous child are ignored. When transport fails, the supervisor must reap the child and report failure. A restart discards all R state.
